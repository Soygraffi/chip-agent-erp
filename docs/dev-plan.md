## 1. 技术方案

### 1.1 技术选型

| 类别 | 选型 | 说明 |
|---|---|---|
| 桌面壳 | Electron（最新稳定版，锁定版本号） | 内置 Chromium，Win10/11 开箱即用，冷启动达标 |
| 前端 | React 18 + TypeScript（strict）+ Vite | electron-vite 三进程构建 |
| UI 组件 | Ant Design 5 + @ant-design/icons | 表格/表单/时间线/弹窗/标签现成，中文本地化 |
| 图表 | ECharts 5 | 首页饼图 |
| 数据库 | better-sqlite3（同步 API，跑在**主进程**） | 配 @electron/rebuild 处理原生模块 ABI |
| Excel | exceljs | 读写 .xlsx（模板生成、导入导出） |
| 压缩 | adm-zip | 备份打包 zip、恢复解压（纯 JS，无原生依赖） |
| 日期 | dayjs | 日期计算（逾期、3 天内、月度区间） |
| 状态管理 | zustand（轻量） | 全局设置、提醒状态；页面数据用自封装 hooks |
| 测试 | vitest | 领域逻辑与数据层单测/集成测试 |
| 打包 | electron-builder（NSIS 安装包 + portable） | Win10/11 x64 |
| 质量 | ESLint + Prettier + husky（可选） | 提交前检查 |

### 1.2 进程模型与分层（为 Web 版复用而设计）

```
渲染进程（React UI）── contextBridge 暴露的 window.api ──▶ 主进程（Electron）
                                                             ├─ IPC 路由层
                                                             ├─ 应用服务层（业务用例编排）
                                                             ├─ 领域层（纯 TS：编号/金额/口径/状态机）★ 可整体复用到 Web
                                                             ├─ 仓储层（better-sqlite3 实现）★ Web 版仅替换为 MySQL 实现
                                                             └─ 基础设施：迁移器/附件管理/备份/Excel
```

- **渲染进程零 DB 访问、零 Node 能力**（contextIsolation 开启），所有数据操作经 typed IPC
- **领域层不 import electron / better-sqlite3 / exceljs**，纯 TypeScript，Web 版直接复用
- 主进程是唯一写入口：每次写操作成功后向渲染进程广播 `data-changed` 事件，首页看板与铃铛订阅后实时刷新（对应 PRD“统计数据实时刷新”）

### 1.4 数据层实现顺序（M1 落地）

1. `migrations/001_init.sql`：直接采用 data-model.md 二章 DDL（12 张表 + 全部索引）
2. `migrations/002_seed.sql`：四章种子数据（5 状态、4 客户类型、4 订单类型、3 付款方式、2 币种+汇率、10 节点模板、默认设置）
3. `migrator.ts`：启动时比对 `schema_meta.schema_version`，顺序执行未应用脚本，事务包裹，失败回滚
4. 仓储层每张表一个 Repo，方法签名即领域层需要的接口（interface 定义在 domain 或 shared，实现放 db），保证 Web 版可替换

## 4. 各里程碑详细任务

### M0 项目脚手架与工程化（2 天）

**目标**：跑通 Electron + React + SQLite 三进程骨架，产出可安装的空壳应用。

- [ ] 初始化 pnpm workspace（apps/desktop + packages/shared、domain、db）
- [ ] electron-vite 工程：main / preload / renderer 三进程模板
- [ ] 接入 AntD 5（中文 locale、ConfigProvider）、React Router、zustand、dayjs、ECharts
- [ ] 主进程接入 better-sqlite3 + @electron/rebuild（验证 ABI 匹配，安装后能建库）
- [ ] 应用布局骨架：左侧导航 + 内容区 + 顶部铃铛占位；所有路由占位页
- [ ] 启动画面 + 窗口参数（尺寸、最小尺寸、高 DPI）
- [ ] electron-builder 配置（NSIS + portable），输出内部安装包
- [ ] ESLint/Prettier、commit 规范、`pnpm dev` / `pnpm build` / `pnpm test` 脚本

**验收**：安装包在干净 Win10/11 机器安装成功；应用启动显示导航与占位页；开发模式热更新正常；空数据库文件自动创建。

### M1 数据层 + 领域核心（4 天）

**目标**：数据库迁移与种子就绪，所有领域算法带单测落地——这是全项目的地基。

- [ ] `migrations/001_init.sql`（照 data-model.md DDL 原样落地，含全部索引与部分唯一索引）
- [ ] `migrations/002_seed.sql`（种子数据）与 `migrator.ts`（schema_version 驱动、事务、失败回滚）
- [ ] 连接管理：WAL、`foreign_keys=ON`、`busy_timeout`、数据目录定位（默认 `%APPDATA%\ChipAgentERP\data`，可被 setting 覆盖）
- [ ] 仓储层 12 个 Repo（CRUD + 分页/筛选查询参数化，防注入用 prepared statement）
- [ ] 领域算法（packages/domain，全部纯函数 + 单测）：
  - [ ] 客户名归一化（trim + NFKC + 小写 + 内部空白压缩）
  - [ ] 订单编号生成（按日重置、撞号顺延、位数/前缀/日期格式可配）
  - [ ] 金额：小计四舍五入、自动汇总、手改标记与恢复
  - [ ] 节点状态机：done 自动填实际时间、自动进入下一节点、全节点完成触发自动完结（单向）
  - [ ] 7 项首页口径（客户总数/跟进中/本月新增/本月金额折 CNY/待发货/逾期/重点跟进）
  - [ ] 提醒计算（非终态 + 三状态 + 计划时间：逾期 / 0–3 天）
  - [ ] Excel 行校验规则（必填、日期格式、字典名称匹配、唯一性）
- [ ] 服务层骨架：CustomerService / OrderService / NodeService / StatsService / ReminderService / DictService / SettingService
- [ ] IPC 路由骨架 + preload typed API + `data-changed` 广播机制
- [ ] 单元/集成测试：domain 全覆盖；db 用内存库跑迁移+种子+CRUD；CI 脚本 `pnpm test`

**验收**：`pnpm test` 全绿；内存库迁移+种子幂等可重复执行；编号/金额/口径/状态机与 data-model.md 六章算法逐条一致（抽查对照）。

### M2 客户管理（3 天）

**目标**：客户增删改查 + 软删除 + 详情 4 Tab 全流程可用。

- [ ] 客户列表页：分页表格（名称/类型/联系人/电话/订单总数/跟进中订单数）、类型与重点客户筛选、全称/简称/联系人模糊搜索、重点客户高亮
- [ ] 客户新建/编辑表单：必填校验（全称唯一提示「客户名称已存在」）、负责人默认取 Windows 用户名
- [ ] 客户详情页：信息卡片 + 快捷编辑 + 4 Tab（全部/跟进中/已完结/已取消，按状态语义分组）+ 页内“为该客户新建订单”入口（跳订单新建并预选客户）
- [ ] 软删除：二次确认（提示订单数、订单将保留）、删除后列表/下拉/判重中消失
- [ ] 订单上客户显示「已删除客户·原名称」（订单列表与详情共用的 CustomerName 组件）
- [ ] 服务层：name_norm 归一化入库、唯一性错误码、软删除事务

**验收**：新增→编辑→检索→详情→软删除全流程走通；重名（含全角/大小写变体）被拦截；删除客户后其订单仍可查看且显示「已删除客户」；对应验收标准 9.1 第 1、2 条。

### M3 订单管理（4 天）

**目标**：订单增删改查 + 物料明细 + 金额与编号规则全部落地。**本里程碑为内部检查点：核心可用版。**

- [ ] 订单列表：多维筛选（客户/状态/类型/订单日期与交期范围）、编号与芯片型号关键字搜索、金额/日期排序、逾期红色高亮 + 「逾期 N 天」角标、金额悬停折人民币
- [ ] 订单新建/编辑：
  - [ ] 编号自动生成预览 + 手动录入（唯一校验）
  - [ ] 客户下拉（带搜索，不含已删除客户）、日期选择器、币种默认人民币 + 汇率快照取值
  - [ ] 物料明细行编辑器：增删行、芯片型号必填、数量整数、单价 4 位、小计实时算、最多 50 行
  - [ ] 总金额自动汇总 + 手改（「已手改」标记 + 一键恢复自动）
  - [ ] 创建成功后自动生成 10 个标准节点（调用 M4 的 NodeService 接口，本里程碑可先落 M1 的临时实现）
- [ ] 订单详情页：信息 + 状态标签（字典配色）+ 明细表 + 时间线占位 + 快捷操作按钮
- [ ] 订单删除：二次确认 + 级联删除（明细/节点/附件/跟进）
- [ ] 单测补充：编号顺延、金额精度（0.1×3 类浮点陷阱）、汇率快照

**验收**：完整建一单（客户→明细→金额→节点自动生成）数据无误；筛选/搜索/排序/逾期高亮正确；对应验收标准 9.1 第 3、4、13 条。

### M4 进度跟踪（4 天）

**目标**：节点全生命周期 + 时间线 + 附件托管 + 状态机闭环。**核心闭环检查点。**

- [ ] 节点自动生成：新建订单/导入订单时按启用模板顺序生成 10 节点（template_id 关联、语义码溯源）
- [ ] 订单详情时间线：倒序垂直时间线、4 色状态、点击展开（跟进历史/附件/负责人/计划实际时间）、未填计划标注「未设计划」
- [ ] 节点编辑：改名、调顺序、删除（级联附件与跟进）、状态四选一
- [ ] 状态机联调：标记已完成→自动填实际时间→下一未开始节点自动变进行中→全节点完成→订单自动置「已完结」（单向）；异常延误记录原因
- [ ] 跟进记录：多次追加，时间戳历史列表
- [ ] 附件：拖拽/选择上传 → 复制进 `attachments/{order_id}/{node_id}/` → 存相对路径；打开文件、打开所在目录、删除（连文件）；50MB/个限制与类型不限
- [ ] 订单删除时清理附件实体文件（防孤儿文件）

**验收**：从新建订单到节点逐个推进到自动完结的完整链路；时间线配色与排序正确；附件上传/打开/随节点删除清理正常；对应验收标准 9.1 第 5、6 条。

## 7. 风险与对策

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| 1 | better-sqlite3 原生模块与 Electron ABI 不匹配 | 启动即崩 | 锁定 Electron 版本，@electron/rebuild 入 CI；M0 首日验证 |
| 2 | 浮点金额误差（0.1×3） | 金额错误 | 金额统一 round(2)，单测覆盖边界；不引入 Decimal 库（V1 够用） |
| 3 | 状态字典随意配置破坏统计 | 口径错乱 | 语义字段引导 + 内置状态保护 + 引用检查 + M8 口径回归测试 |
| 4 | 冷启动 > 3s | 验收不过 | 启动画面 + 主进程轻量化 + 懒加载；M9 实测预留优化时间 |
| 5 | 附件大文件导致备份/迁移缓慢 | 体验差 | 50MB 单文件限制；备份/迁移带进度提示 |
| 6 | WAL 模式下备份不一致 | 备份损坏 | 备份前 wal_checkpoint(TRUNCATE)；恢复前校验 zip 与库完整性 |
| 7 | 数据目录迁移中断（断电/杀进程） | 数据风险 | 先复制后切换、旧目录保留回退；迁移过程写锁 |
| 8 | exceljs 对非标准 Excel 兼容性 | 导入失败 | 模板固定格式 + 逐行校验报告；不支持的文件类型明确报错 |
| 9 | 需求理解偏差（口径细节） | 返工 | 里程碑验收对照 PRD 章节；M3/M6 检查点请用户试用确认 |
| 10 | 单人开发瓶颈 | 延期 | 8 周含 20% 缓冲；若压缩工期，优先砍 E2E 与可选增强 |
