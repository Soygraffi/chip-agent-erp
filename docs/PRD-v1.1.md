### 修订说明（V1.0 → V1.1）

本版依据对 V1.0 文档的逐项评审（共 19 项决策，见附录 A）修订，主要变化：

1. **交付范围明确化**：原第四章“详细功能需求”与第九章“验收标准”已包含首页看板、节点提醒、Excel 导入导出、附件、备份恢复等能力，而原第八章将其划入 V1.1，两处矛盾。本版统一：**原四、九章全量内容均属于产品 V1.0 发布范围**，第八章版本规划重排。
2. **删除两项功能**：4.6.4“启动密码设置”与 4.6.5“数据清理”自 V1.0 移除。密码保护、数据库加密移入产品 V1.1 评估；数据清理功能直接取消（不给误删机会）。
3. **补齐口径定义**：逾期订单、待发货订单、跟进中订单、本月金额等所有统计指标均给出精确算法（见 4.1.3）。
4. **解决业务规则冲突**：客户删除改为软删除；订单总金额“自动汇总 + 允许手改”；客户详情 Tab 与 5 种订单状态的对齐；订单状态字典可配置后的语义标记方案。
5. **明确关键流程**：新建订单自动生成 10 个标准节点；附件托管与备份打包方案；订单编号按日重置规则；Excel 导入的客户匹配规则；数据库路径迁移行为。

## 一、产品概述

### 1.1 产品背景

芯片代理商业务员日常需同时对接多家客户、跟进数十个订单，每个订单覆盖需求沟通、报价、下单、备货、发货、对账、收款等多个环节。当前业务数据分散在 Excel、邮件、微信聊天记录中，存在以下核心痛点：

1. 客户信息零散，查找客户资料与历史订单耗时久
2. 多订单并行推进，进度节点依赖人工记忆，易遗漏跟进、造成交期延误
3. 芯片型号、规格、单价、交期等明细信息分散，无法快速追溯订单全链路
4. 缺乏统一数据看板，无法快速掌握当月订单量、逾期订单、回款进度等核心数据

为解决上述问题，先开发**本地单机桌面版**工具，实现以客户为中心的订单全流程进度管理；产品架构预留扩展能力，后续可无缝升级为支持多账号协同的 Web 平台。

### 1.2 产品定位

面向芯片代理商业务员的**本地化客户订单全生命周期管理工具**，聚焦「客户-订单-进度」三级数据管理，替代碎片化的 Excel 记录，实现订单进度可追溯、业务数据可统计、本地数据安全可控。

### 1.3 产品目标

1. 建立统一的客户与订单数据体系，实现订单信息查询效率提升 70% 以上
2. 标准化订单进度节点，实现订单全流程可追溯，漏跟进、逾期订单率降为 0
3. 核心业务数据可视化，快速掌握订单整体进度与业务概况
4. 数据 100% 本地存储，支持备份恢复，保障业务数据安全
5. 产品架构预留扩展空间，后续升级 Web 协同版时业务数据可完整迁移

### 1.4 目标用户

- **当前版本（V1.0）**：芯片代理商业务员（单人本地使用）
- **后续版本（V2.0）**：业务员、销售主管、财务人员、系统管理员（多角色协同）

## 三、产品整体架构

系统采用「客户为核心，订单为载体，进度节点为跟踪主线」的三级结构，辅以数据统计、系统配置能力。

```
客户订单进度管理系统
├── 首页看板（指标卡片 / 状态分布 / 逾期与重点订单 / 快捷入口）
├── 客户管理
│   ├── 客户列表（筛选 / 搜索 / 重点客户高亮）
│   ├── 客户详情（基础信息 + 4 个订单 Tab）
│   └── 客户增删改（软删除）
├── 订单管理
│   ├── 订单列表（多维度筛选 / 排序 / 逾期高亮）
│   ├── 订单详情（信息 + 物料明细 + 进度时间线）
│   ├── 订单增删改
│   └── 订单物料明细
├── 进度跟踪
│   ├── 进度节点管理（模板自动生成 / 增删改排序）
│   ├── 进度时间线展示
│   └── 到期/逾期提醒（启动弹窗 + 应用内铃铛）
├── 数据工具
│   ├── Excel 导入导出
│   └── 数据备份与恢复（db + 附件打包）
└── 系统设置
    ├── 基础字典配置（含订单状态语义标记）
    ├── 编号规则设置
    ├── 汇率设置
    └── 存储设置（数据目录迁移）
```

## 四、详细功能需求

### 4.1 首页看板

**功能描述**：软件启动后默认展示首页，呈现核心业务概览与快捷入口。

#### 4.1.1 核心指标卡片

展示 7 个指标：客户总数、跟进中订单数、本月新增订单数、本月订单总金额、待发货订单数、逾期订单数、重点跟进订单数。

#### 4.1.2 订单状态分布

以饼图展示所有订单的状态占比。状态来自订单状态字典（可含自定义状态），动态聚合；图例颜色取状态字典配置的颜色。

#### 4.1.3 指标口径定义（本版新增，所有统计均以此为准）

| 指标 | 精确算法 |
|---|---|
| 客户总数 | 未删除（未软删除）的客户数量 |
| 跟进中订单数 | 订单状态为非终态（终态标记为“否”）的订单数量，即待确认/进行中/已发货及自定义非终态状态 |
| 本月新增订单数 | “订单日期”落在当前自然月的订单数量 |
| 本月订单总金额 | 订单日期在当前自然月、且状态结果非“取消”的订单；每单取其有效总金额（手改则以手改值为准）按订单上的汇率快照折合人民币后求和，保留 2 位小数 |
| 待发货订单数 | 订单非终态，且其下“到货入库”节点（按节点模板语义码 `arrival` 识别）状态为已完成，且“发货中”节点（语义码 `ship`）状态未完成的订单数量 |
| 逾期订单数 | “预计交货日期”早于今天，且订单状态为非终态的订单数量 |
| 重点跟进订单数 | 标记“重点跟进”且状态为非终态的订单数量 |

#### 4.1.4 逾期 & 重点订单列表

- 已逾期订单优先展示，红色高亮，按逾期天数倒序排列（逾期越久越靠前）
- 展示标记为“重点跟进”的订单，支持一键跳转订单详情

#### 4.1.5 快捷操作入口

“新建客户”“新建订单”两个高频操作按钮固定展示。

**业务规则**：

- 统计数据实时刷新，数据变更后首页指标自动更新
- 已软删除客户名下的订单仍计入全部统计（订单本身未删除）；仅“客户总数”不含软删除客户

### 4.2 客户管理模块

**功能描述**：维护全量客户基础信息，所有订单归属到对应客户名下，实现以客户为维度的订单聚合。

#### 4.2.1 客户新增与编辑

- **字段定义**：
  - 必填项：客户全称（唯一）、客户类型（字典，可配置）、联系人、联系电话
  - 选填项：客户简称、邮箱、地址、负责业务员、合作起始日期、备注
  - 标记项：是否重点客户（是则列表高亮）
- **唯一性规则（本版细化）**：
  - 客户全称判重前做归一化：去除首尾空格、全角字符转半角、字母忽略大小写；判断对象仅为**未删除**客户
  - 重复提交时提示「客户名称已存在」；数据库中保留用户原始输入写法
- **业务规则**：
  - 编辑客户时，历史关联订单不受影响
  - 负责业务员默认取当前 Windows 用户名，可修改

#### 4.2.2 客户列表与检索

- 表格列：客户名称、客户类型、联系人、联系电话、订单总数、跟进中订单数
- 筛选：客户类型、是否重点客户
- 搜索：客户全称、简称、联系人关键字模糊匹配
- 点击客户名称进入客户详情页；重点客户整行高亮
- 已删除客户不出现在列表中

#### 4.2.3 客户详情页

- 顶部展示客户基础信息卡片，支持快捷编辑
- 下方 4 个 Tab，**按订单状态的语义分组**：

| Tab | 包含的订单 |
|---|---|
| 全部订单 | 该客户所有订单（含终态） |
| 跟进中订单 | 状态非终态的订单（待确认/进行中/已发货/自定义非终态） |
| 已完结订单 | 终态且结果=“完成”的订单 |
| 已取消订单 | 终态且结果=“取消”的订单 |

- 详情页内支持直接为该客户新建订单（客户自动选中）

#### 4.2.4 客户删除（本版改为软删除）

- 删除客户时弹出二次确认框，提示「该客户下存在 X 个订单，删除后订单数据将保留」
- 删除 = **软删除**：客户从客户列表、新建订单的客户下拉、客户同名校验中移除，但数据保留在库中
- 其名下订单**全部保留**，在订单列表、首页统计、逾期提醒中照常参与；订单上的客户显示为「已删除客户·原名称」
- 原 PRD 的“删除客户及所有关联订单”级联选项取消；确需删除订单的，到订单列表单独删除
- 软删除不提供恢复入口（V1 无回收站）；删除操作即时生效

### 4.3 订单管理模块

**功能描述**：管理所有订单的基础信息与芯片物料明细，关联对应客户。

#### 4.3.1 订单新增与编辑

- **基础信息字段**：
  - 必填项：订单编号、所属客户、订单日期、订单类型、订单状态
  - 选填项：预计交货日期、实际交货日期、币种（默认人民币）、订单总金额、付款方式、负责人、是否重点跟进、备注
- **订单编号规则（本版明确）**：
  - 格式：`{前缀}{日期}{流水}`，默认 `XS` + `YYYYMMDD` + 4 位流水，如 `XS202610280001`
  - 流水号**按日重置**（每日从 0001 起）
  - 自动生成时取当天日期、当日最大流水 +1；若与既有手动编号撞号，自动顺延取下一个可用号
  - 支持手动录入：任意字符串均可，仅校验全局唯一（去除首尾空格后判重）
  - 前缀、日期格式、流水位数可在系统设置中配置；无论规则如何，全局唯一由数据库唯一索引兜底
- **所属客户**：从客户列表中下拉选择（不含已删除客户），不可手动输入
- **订单类型**：字典可配置，系统预置：样品单、批量订单、备货订单、返单
- **订单状态**：字典可配置（见 4.6.1），系统预置 5 个：待确认、进行中、已发货、已完结、已取消
- **币种与汇率**：币种为字典；下单时从汇率设置中取该币种当前汇率，**快照**到订单上；此后修改汇率设置不影响历史订单
- **金额规则（本版明确）**：
  - 明细小计 = 数量 × 单价，四舍五入保留 2 位小数
  - 订单总金额默认 = 全部明细小计之和（保留 2 位小数），实时自动计算；无明细时为 0
  - **允许手动修改总金额**（用于折扣、运费、整单议价）；手改后标记「已手改」，不再随明细变化；可一键恢复自动汇总
  - 数量为整数；单价保留 4 位小数；金额保留 2 位小数

- **订单物料明细**：
  - 支持多行增删，每行对应一款芯片物料
  - 字段：芯片型号（必填）、品牌、封装规格、需求数量（必填，整数）、单价、小计金额（自动）、客户料号、备注
  - 单订单最多 50 条明细

- **订单状态自动完结（本版明确）**：
  - 订单的**全部**进度节点状态均为「已完成」、且节点数量大于 0 时，系统自动将订单状态置为“默认完成状态”（字典中标记为默认完成的状态，预置为「已完结」）
  - 该联动为**单向**：自动置完结后，用户可手动改回任何状态；改回后节点若再次全部完成仍会再次触发
  - 节点数为 0 的订单不触发自动完结

#### 4.3.2 订单列表与筛选

- 表格列：订单编号、客户名称、订单类型、订单金额、订单状态、预计交期、负责人
- 多维度筛选：
  - 按客户名称筛选（下拉，含搜索）
  - 按订单状态、订单类型筛选
  - 按订单日期、预计交期的时间范围筛选
- 关键字搜索：订单编号、芯片型号模糊匹配（芯片型号跨明细表匹配）
- 排序：按金额、订单日期、预计交期升降序
- 逾期订单（派生标记：交期已过且非终态）在列表中红色高亮，状态旁显示「逾期 N 天」角标（N = 今天 − 预计交货日期）
- 金额列展示原币金额；鼠标悬停显示折合人民币金额（按订单汇率快照）

#### 4.3.3 订单详情页

- 顶部：订单基础信息与状态标签，标签配色取状态字典配置（预置：待确认灰、进行中蓝、已发货青、已完结绿、已取消深灰）；逾期订单叠加红色「逾期 N 天」角标
- 中部：订单物料明细表格
- 下方：进度时间线区域，展示全量进度节点（见 4.4.2）
- 快捷操作：编辑订单、新增进度节点、导出订单详情

#### 4.3.4 订单删除

- 删除订单需二次确认，删除后关联的物料明细、进度节点、节点附件、跟进记录一并删除
- 删除操作不可撤销（可通过历史备份找回）

### 4.4 进度跟踪模块（核心功能）

**功能描述**：每个订单对应多阶段进度节点，以时间线形式可视化展示，实现订单全流程可追溯。

#### 4.4.1 进度节点模板与生成

- **系统预设标准节点模板**（10 个，可在系统设置中增删改、排序）：

| 顺序 | 名称 | 语义码（内部固定） |
|---|---|---|
| 1 | 需求沟通 | demand |
| 2 | 报价中 | quote |
| 3 | 客户确认 | confirm |
| 4 | 下达采购 | purchase |
| 5 | 供应商备货/排产 | stock |
| 6 | 到货入库 | arrival |
| 7 | 发货中 | ship |
| 8 | 客户签收 | sign |
| 9 | 对账开票 | invoice |
| 10 | 收款完成 | payment |

- **节点自动生成（本版明确）**：新建订单（含 Excel 导入的订单）时，按当前启用的节点模板顺序自动生成 10 个节点实例，初始状态「未开始」，计划时间留空
- 用户可删除不适用节点、新增自定义节点、调整节点顺序
- 语义码只存在于模板上，供“待发货”等统计口径使用；自定义节点无语义码

#### 4.4.2 节点字段与状态

每个节点包含字段：

- 节点名称（必填）
- 计划完成时间（选填；未填的节点不参与到期提醒，时间线上标注「未设计划」）
- 实际完成时间（选填；标记「已完成」时若为空，自动填入当天日期，可修改）
- 节点状态（固定 4 值，不可配置）：未开始、进行中、已完成、异常延误
- 跟进记录：文本，描述跟进内容；支持多次追加，形成该节点的跟进历史（每条带时间戳）
- 附件：本地文件，每节点可传多个，单文件 ≤ 50MB，不限类型
- 负责人：默认继承订单负责人，可改

**节点状态流转规则**：

- 节点标记为「已完成」时，若存在下一个「未开始」节点，自动将其置为「进行中」（即 PRD 5.2“自动进入下一节点”的落地规则）；若是最后一个节点，触发订单自动完结检查
- 节点标记「异常延误」时，提示填写原因（写入跟进记录），异常延误节点同时参与逾期提醒
- 节点可删除（连带其附件与跟进记录）；删除节点可能影响“待发货”统计（统计口径基于语义码），属预期行为

#### 4.4.3 进度时间线展示

- 订单详情页以垂直时间线**倒序**展示所有节点（最新节点在最上方）
- 配色规则：已完成绿色、进行中蓝色、未开始灰色、异常延误红色
- 点击节点展开：跟进记录历史、附件列表（可打开文件/打开所在目录）、负责人、计划与实际时间
- 支持在时间线内直接编辑节点（改状态、填时间、写跟进、传附件）

#### 4.4.4 到期与逾期提醒（本版升级）

- **提醒对象**：同时满足以下条件的节点
  - 所属订单状态为非终态
  - 节点状态 ∈ {未开始、进行中、异常延误}
  - 已填写计划完成时间
- **分类**：
  - 已逾期：计划完成时间早于今天
  - 即将到期：今天 ≤ 计划完成时间 ≤ 今天+3 天（“3 天内”含今天）
- **触达方式（两处）**：
  1. 软件启动时弹出提醒窗口，分组列出两类节点（订单编号、客户、节点名、计划时间、逾期天数），点击任一提醒跳转到对应订单详情并定位节点；窗口提供「今日不再提示」
  2. 应用内左侧导航常驻**铃铛提醒**：角标数字 = 逾期节点数；只有即将到期时显示橙色圆点；点击弹出提醒面板，数据变更后实时刷新
- 同一订单同时有逾期与即将到期节点时，只按最紧急（逾期）呈现

### 4.5 数据工具模块

#### 4.5.1 Excel 导入导出

- **导出**（均为 .xlsx，文件名自动附加导出时间）：
  - 客户列表：当前筛选结果或全部（导出前可选范围）
  - 订单列表：当前筛选结果或全部；列含订单编号、客户、类型、状态、原币金额、折人民币金额、订单日期、预计交期、负责人、备注
  - 订单明细：全部订单的物料明细，列含订单编号、客户、芯片型号、品牌、封装、数量、单价、小计、客户料号、备注
  - 订单详情（单订单）：一个文件 3 个 sheet——订单信息 / 物料明细 / 进度节点（节点名称、状态、计划时间、实际时间、跟进记录、负责人）
- **导入**：
  - 提供标准 Excel 模板（客户模板、订单模板），可一键下载
  - 客户导入：校验必填项与客户全称唯一性；重复客户自动跳过
  - 订单导入：字段含订单编号、客户全称、订单日期、订单类型、订单状态、币种、金额、预计交期、负责人、备注、是否重点跟进
    - **客户匹配规则**：按客户全称精确匹配（同样先归一化），客户必须已存在，匹配不上则该行失败并提示
    - 订单编号留空则按编号规则自动生成；填写则校验唯一
    - 订单类型/订单状态/币种按字典名称匹配，匹配不上该行失败
    - 币种留空默认人民币；金额留空则按“自动汇总”（无明细时为 0）
    - 导入成功时同样自动生成 10 个标准节点（与手工新建一致）
  - 逐行处理、逐行报错，不整批回滚；完成后展示成功条数、失败条数及每条的失败原因（行号 + 原因）
  - 导入不包含物料明细与进度节点（模板仅订单基础信息）

#### 4.5.2 数据备份与恢复

- **备份**：
  - 一键打包为 zip：数据库文件 + 附件目录 + `manifest.json`（应用版本、数据模型版本、备份时间、数据库校验值）
  - 备份文件命名自动附加日期时间：`backup_YYYYMMDD_HHmmss.zip`
  - 默认保存到设置中的备份默认路径；单次可临时另选目录
- **恢复**：
  - 选择历史备份 zip 后，校验 zip 完整性与 manifest、试打开数据库
  - 校验通过后强制提示「恢复将覆盖当前所有数据，是否继续？」
  - 恢复前系统**自动**将当前数据（含附件）备份到备份目录（命名 `pre_restore_YYYYMMDD_HHmmss.zip`）
  - 覆盖数据库与附件目录后提示重启应用，重启后生效
- **附件保障**：备份/恢复均包含附件目录，附件与数据库作为一个整体，不存在“恢复后附件失效”问题

### 4.6 系统设置模块

#### 4.6.1 基础字典配置

- 可配置字典：客户类型、订单类型、付款方式、币种、节点模板、订单状态
- 所有字典项支持增、删、改、排序、启用/停用、颜色（状态类）
- **删除保护**：字典项被业务数据引用时禁止删除，提示引用数量
- **订单状态字典的特殊语义（本版新增，支撑统计与自动化）**，每个状态带：

| 属性 | 说明 |
|---|---|
| 名称 | 显示名，可改 |
| 颜色 | 状态标签与饼图颜色，可改 |
| 是否终态 | 终态订单不计入“跟进中/逾期/待发货”等非终态口径 |
| 终态结果 | 终态时二选一：完成 / 取消（客户详情 Tab、本月金额统计依据） |
| 是否默认完成状态 | 全节点完成时自动写入的状态（全局仅一个，预置为「已完结」） |

- 预置 5 个状态：待确认（灰，非终态）、进行中（蓝，非终态）、已发货（青，非终态）、已完结（绿，终态·完成·默认完成）、已取消（深灰，终态·取消）
- 节点状态（未开始/进行中/已完成/异常延误）为代码内固定枚举，不开放配置

#### 4.6.2 订单编号规则

- 可配置：前缀（默认 `XS`）、日期格式（默认 `YYYYMMDD`）、流水位数（默认 4，范围 2–6）
- 重置周期固定为**按日重置**（本版决策，不可配）

#### 4.6.3 汇率设置（本版新增）

- 为每种币种维护一个手工汇率（对人民币，保留 6 位小数）
- 下单时快照到订单；修改汇率只影响之后新建的订单，不影响历史订单与历史统计

#### 4.6.4 存储设置

- **数据目录**：默认 `%APPDATA%\ChipAgentERP\data`，内含数据库文件与附件目录
- **修改数据目录路径**：应用暂停写入，将整个数据目录（库 + 附件）复制到新路径并校验，成功后切换；**旧目录保留**不删除，作为回退
- **备份默认路径**：默认 `<数据目录>\backups`，可改

## 五、核心业务流程

### 5.1 订单全生命周期主流程

```
新建客户 → 为客户创建订单（自动生成编号 + 10 个标准节点）→ 录入芯片明细（小计/总金额自动算）
    ↓
维护各阶段进度节点（改状态、填时间、写跟进、传附件）
    ↓
节点全部完成 → 订单自动置为「已完结」→ 归档留存
```

### 5.2 进度跟进流程

1. 进入订单详情页，查看当前所处进度节点
2. 节点推进时，编辑对应进度节点
3. 填写实际完成时间、追加跟进记录，上传相关附件
4. 更新节点状态为「已完成」，自动进入下一节点（下一「未开始」节点置为「进行中」）
5. 如遇异常，标记节点为「异常延误」，记录原因与预计解决时间（写入跟进记录）

## 六、非功能需求

### 6.1 性能需求

- 软件冷启动时间 ≤ 3 秒
- 客户/订单数据量 1000 条以内时，列表查询、搜索响应 ≤ 1 秒
- 单订单支持最多 50 条物料明细、100 个进度节点
- Excel 导入 1000 条数据耗时 ≤ 5 秒

### 6.2 数据安全

- 所有业务数据 100% 存储在本地，无任何网络上传、同步行为
- 关键删除操作（客户、订单、节点）强制二次确认，避免误操作丢失数据
- 客户删除采用软删除，业务数据不物理丢失
- 支持手动全量备份（数据库 + 附件整体打包），恢复前自动备份当前数据
- 数据库文件加密、启动密码自 V1.0 移除，移入产品 V1.1 评估

### 6.3 易用性

- 采用左侧导航 + 右侧内容的经典桌面软件布局，学习成本低
- 新建客户、新建订单等高频操作不超过 3 步完成
- 表单支持 Tab 键切换输入框、回车键快速提交
- 所有删除等危险操作均有明确二次确认

### 6.4 兼容性

- 支持 Windows 10 / Windows 11 64 位操作系统
- Electron 打包内置 Chromium 运行环境，用户电脑无需额外安装依赖
- 支持高 DPI 屏幕自适应显示

### 6.5 可扩展性

- 数据库表结构预留扩展字段，带数据模型版本号（schema_version），后续升级自动迁移
- 业务逻辑与界面层分离：领域逻辑独立于 Electron 主进程封装，后续升级 Web 版时业务代码可高复用
- 采用标准 SQLite 数据库，后续迁移至 MySQL 等关系型数据库成本低
- 附件采用“托管目录 + 数据库存相对路径”方案，后续迁移/换机/上云成本低

## 七、数据实体说明

核心数据实体关系：

- **客户** 1 : N **订单**（一个客户对应多个订单；客户软删除不影响订单）
- **订单** 1 : N **订单明细**（一个订单对应多款芯片物料）
- **订单** 1 : N **进度节点**（一个订单对应多个进度阶段）
- **进度节点** 1 : N **节点附件**、1 : N **跟进记录**
- **字典**（客户类型/订单类型/付款方式/币种/节点模板）与 **订单状态字典** 被客户、订单引用
- **汇率表** 为每种币种维护汇率，订单保存汇率快照

核心实体关键字段：

1. **客户**：客户ID、客户名称（全称/简称）、归一化名称、客户类型、联系人、联系方式、地址、负责业务员、合作起始日期、是否重点客户、备注、删除标记/时间
2. **订单**：订单ID、订单编号、关联客户ID、订单类型、订单状态、订单日期、预计/实际交货日期、币种、汇率快照、总金额、金额是否手改、付款方式、负责人、是否重点跟进、备注
3. **订单明细**：明细ID、关联订单ID、芯片型号、品牌、封装、数量、单价、小计、客户料号、备注
4. **进度节点**：节点ID、关联订单ID、模板ID/语义码、节点名称、计划时间、实际时间、节点状态、负责人、排序
5. **节点跟进记录**：记录ID、关联节点ID、内容、时间
6. **节点附件**：附件ID、关联节点ID、原文件名、托管相对路径、大小

> 完整表结构、DDL、索引、字典语义与种子数据见《数据模型设计》（`docs/data-model.md`）。

## 九、验收标准

### 9.1 功能验收

1. 可正常新增、编辑、删除客户；客户全称唯一性校验（归一化判重、仅未删除客户）生效
2. 删除客户为软删除且有二次确认，删除后客户从列表消失、订单保留并显示「已删除客户·原名称」，订单仍计入统计
3. 可关联客户创建订单：编号按规则自动生成（按日重置、撞号顺延）、手动编号唯一性校验生效；自动生成 10 个标准节点
4. 多行物料明细录入，小计与总金额自动计算正确；手改总金额有「已手改」标记且可恢复自动
5. 全部节点标记完成后订单自动置为「已完结」；节点完成自动进入下一节点
6. 订单下可新增、删除、排序进度节点，时间线倒序展示正常，四种节点状态配色正确
7. 支持按客户、状态、类型、日期范围筛选，按编号/芯片型号搜索，按金额/日期排序，结果准确
8. 首页 7 个指标数值与 4.1.3 口径定义一致；状态分布饼图与实际状态一致；逾期订单红色高亮且按逾期天数倒序
9. 软件启动时正确识别并提示逾期、即将到期（3 天内，含今天）的节点（仅非终态订单）；应用内铃铛角标实时刷新；提醒可跳转对应订单详情
10. 可成功导出 Excel（客户/订单/明细/单订单 3-sheet 详情），内容与系统数据一致，导出范围（筛选结果/全部）可切换
11. Excel 导入：模板可下载；必填与唯一性校验生效；订单按客户全称精确匹配、客户不存在则该行失败；重复数据跳过；完成后展示成功/失败条数与原因
12. 备份可生成 zip（数据库 + 附件 + manifest）；恢复前自动备份当前数据，恢复后数据完整、附件可正常打开
13. 删除订单有二次确认，删除后明细、节点、附件、跟进记录一并删除
14. 字典可增删改，被业务数据引用的项禁止删除；订单状态字典的终态/结果/默认完成标记生效并正确驱动统计与自动完结
15. 修改数据目录后数据完整迁移到新路径，旧目录保留

### 9.2 非功能验收

1. 软件冷启动时间不超过 3 秒，列表查询响应流畅无卡顿（1000 条数据内 ≤ 1 秒）
2. 关闭网络环境下可正常使用全部功能
3. 重装软件后，通过备份文件可完整恢复所有业务数据（含附件）
4. 高 DPI 屏幕下界面显示正常
